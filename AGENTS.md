# hfctl — деплой и управление hipfire-сервером (продукт)

Продукт: CLI `hfctl` (диспетчер `hfctl` + `lib/*.sh` + `tpl/`) для постановки
и обслуживания сервера hipfire на «голой» Ubuntu/Debian (AMD Strix Halo /
gfx11xx). Лейаут v2: git-клон = стек (`./hfctl on` на пустом клоне —
bootstrap; машинное состояние — в gitignored `.data/`). Никакой привязки к
конкретной инфраструктуре: адреса, ключи, хост-профили — не здесь
(исследования и железо — в отдельном проекте llm-lab).

Язык ответов — русский. Ответы подробные — но на простых задачах (быстрый
вопрос, односложная проверка, мелкая правка) размышлять коротко и по
существу, без перебора гипотез.

## Что в репо

- `hfctl` — сам CLI (диспетчер + `lib/` + `tpl/`); живёт в клоне
  (`~/hfctl/hfctl`, запуск из любого каталога клона), `~/.local/bin/hfctl` =
  симлинк (ставит bootstrap). Обновление кода — `git pull` в клоне; recreate
  — `use` (или `off`/`on`).
- `.gitignore` — `.data/` и `.env`: машинное состояние (модели, профили,
  bench-runs, маркеры/лок) и канон профиля вне git; `git clean -fd`
  безопасен, `git clean -fdx` удаляет `.data/` — запрещён.
- `README.md` — публичное лицо: quickstart, команды, профили.
- `.dev/` — blackboard dev-flow (карта — `.dev/README.md`): `SPEC.md`
  (UX-спецификация), `PLAN.md` (этапы с DoD), `STATE.md` (трекер состояния —
  единственная точка правды «что сделано / какой этап»; обновлять статусным
  коммитом), `DECISIONS.md`, `FACTS.md`, `history.md`, `tasks/<stage>/<stage>.<sub>/`
  (документы сабстэджа), `external/` (EXP-очередь), `archive/`.
- `tpl/bench/merge_sort_thinking_off.txt` — bench-фикстура (канон); md5
  зафиксирован (`BENCH_FIXTURE_MD5` в `lib/bench.sh`), не редактировать байты
  (любая правка меняет хеш и сравнимость замеров).

## Development protocol: dev-flow

- **Blackboard**: `/workspace/hfctl/.dev/` (layout: STATE.md, history.md,
  SPEC.md, PLAN.md, FACTS.md, DECISIONS.md, `tasks/<stage>/<stage>.<sub>/`,
  `external/`, `archive/`; карта — `.dev/README.md`).
- **Internal checks** (роли запускают сами): `bash -n hfctl lib/*.sh`;
  `python3 -m py_compile tpl/python/*.py`; `hfctl` без аргументов → usage, rc=1;
  `hfctl status --json` с подменой PORT на чанковый (отказ должен быть
  корректным, не крашем). Зависимостей нет — ничего ставить.
- **External checks** (BLOCKED-EXTERNAL): всё, что требует живого контейнера/
  хоста — TUI на SSH-TTY, реальные /sys-датчики, `podman logs`, живой /stats;
  приёмка на реальных машинах только через EXP-скрипты + явное GO пользователя.
- **Environment hygiene**: роли НЕ делают ssh/podman наружу, не трогают
  /workspace/llm-lab, не правят `tpl/bench/merge_sort_thinking_off.txt` (md5
  канон), не коммитят (коммиты — оркестратор после закрытия сабстэджа),
  не правят `.dev/STATE.md` (обновляет оркестратор статусным коммитом).
- **Code conventions**: диспетчер `hfctl` + `lib/*.sh` + `tpl/`; bash-комментарии
  с `# Назначение / Побочные эффекты / Ограничения / @param / @stdout / @returns`
  на русском (домашний стиль `lib/commands.sh`); python — только stdlib,
  один файл = одна роль в `tpl/python/`; в репо нет IP, имён хостов, путей
  ключей (правило 7).

## Правила разработки

1. Начинаешь работу — прочитай `.dev/STATE.md`; любой коммит, меняющий
   статус этапа/пункта, обновляет `.dev/STATE.md` в себе же.
2. Изменения целевого конфига сервера — только через код профилей hfctl
   (таблица в шапке), не руками в volume.
3. После любой смены конфига: recreate → wait_health → smoke (порядок
   фиксированный).
4. RAM-гейты и прочие префлайты — ДО любого скачивания, отказ с цифрами.
5. Обновление дерева на живой машине — `git pull` в клоне; recreate контейнера
   — `hfctl use` (или `off`/`on`; recreate обязан пересоздать контейнер с
   новым маунтом; ручной cp в обход оставляет контейнер со старым маунтом).
6. Приёмка любого изменения — полный цикл (use ↔ use, off/on, reboot)
   на реальной машине, прежде чем пункт DoD закрывается.
7. В репо не должно появляться: IP-адресов, путей ключей, имён хостов,
   логов с реальных машин (их место — в лабораторном проекте).
