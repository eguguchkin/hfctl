# Brief: bench/concurrency — параллельное сравнение в `hfctl bench`

Пункт 6 продуктового бэклога (hflab STATE.md, срез 2026-11-14). Прообраз —
движковый `hipfire bench --concurrency` (есть с 0.4.5, в 0.4.6 развит;
recon hflab `flow/recon/0.4.6-recon.md` в.6).

## Goal

Одной командой `hfctl bench` пользователь получает параллельную картину
(N клиентов) и может сравнить её с прежним прогоном (`--compare`), чтобы
видеть деградацию/рост агрегата при смене образа/профиля — сейчас quick/full
меряют только solo-сценарии, параллельная регрессия 0.4.6 оставалась
неподтверждённой (ручной `conc_bench.sh`/`par_test.sh` в hflab — костыль).

## Что проектирует architect (решения за ним, рамки — здесь)

1. UX: минимальная форма — например `hfctl bench --parallel N[,M…]`
   (сценарии поверх существующих quick/full или отдельным блоком), вывод
   агрегат + разброс + позиция в очереди; интеграция с `--compare` (артефакт
   JSON уже содержит сценарии — расширить формат параллельными записями,
   совместимость со СТАРЫМИ артефактами quick/full не ломать: их сравнение
   обязана печатать и новая версия).
2. Метрика честности (D8 в .dev/DECISIONS.md): движок отдаёт per-request
   сводки в лог (`[req …] tau=… tok/s=…`), /stats даёт `queue_depth`,
   /metrics — гистограммы; live-скорости в процессе нет. Что показываем в
   параллельном блоке: wall per-request (замер клиента — единственный
   достоверный), агрегат tok/s (сумма токенов/wall окна),Median TTFT по
   гистограмме — architect решает состав, но ВСЁ должно быть либо с пола
   (curl), либо из готовых счётчиков, с явными подписями источника.
3. Нагрузка щадящая: N≤8, промпты фикстуры tpl/bench (md5 253c7ac5 — не
   менять), никаких правок движка/конфига; режим обязан прерываться Ctrl-C
   без мусора в bench-runs.
4. На gfx-роутах разных профилей semantics различается (flash-multi lanes:
   параллельность реальна; 27b-single: FIFO-очередь — wall растёт по позиции).
   Вывод обязан это отражать (роут уже печатается в шапке bench).

## Приёмка (DoD — детализирует architect)

- Внутренние: selfcheck/парсеры артефактов, совместимость --compare со
  старыми JSON (завести фикстуру старого артефакта в test), bash -n, usage.
- Внешние (EXP, окна на ОДНОЙ машине за раз, предупреждение пользователя
  заранее — правило 2026-11-14):
  EXP-1 машина B flash-multi: `--parallel 2` и `4`, домены: агрегат сопоставим
  с историческими 60.3/64.5 (0.4.5; 0.4.6 solo подтверждён 75.8), JSON-артефакт
  + повторный `--compare` показывают корректную дельту;
  EXP-2 che-evo 27b-single: параллельный прогон показывает FIFO-картину
  (wall по позициям растёт, соло не деградировал) — это же закрывает хвост
  «full-матрица N=2/N=4 на 0.4.6 не перепускалась»;
  откат-безопасность: Ctrl-C посреди прогона, битый /health — вменяемые rc.
- Реальные EXP-результаты — hflab `.local-analysis/` (правило 7 / D10).

## Constraints and traps

- tpl/bench/ не трогать; промпты для параллельных сценариев — из существующих
  фикстур (код/проза), не выдумывать новые тексты (иначе τ несравним).
- Параллельные curl'ы: чистка старых resp_* перед прогоном (грабля par_test
  в hflab AGENTS.md №4); UTF-8/кириллица в логах — не ломать парсеры.
- Не смешивать параллельный блок сsolo-прогревом: прогрев один незамеряемый
  запрос, как сейчас.
- D12: доставка на машины одним пакетом после пуша; перепуски — только
  новые EXP.
