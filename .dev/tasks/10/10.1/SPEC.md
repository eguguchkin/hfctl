# SPEC: расширение `hfctl watch` (дашборд)

Источники истины продукта: `spec/hfctl.md` (UX-спецификация) и `spec/plan.md`
(этапы). Этот файл — спецификация подэтапа `watch-tui`; конфликт «что» решается
в пользу `spec/hfctl.md`.

## Требования (формулировка пользователя, 2026-11-12)

1. Скорость префилла — сейчас 0 информации, должна быть видна.
2. Логи контейнера в реальном времени.
3. Доступная память в системе.
4. Частота и мощность видеокарты.
5. Температура процессора.
6. Обновляемый TUI-интерфейс с расчёрченной на прямоугольные блоки раскладкой
   (как htop / amdtop / k9s), а не строки.

## Зафиксированные решения пользователя (см. DECISIONS.md)

- `hfctl watch` в TTY = TUI; в не-TTY (пайп, лог-файл) = стриминг строк.
- Стрим-режим: строчка выводится БЕСУСЛОВНО ровно раз в N секунд (текущий
  «только при изменении счётчиков» упускает всплески температуры); в строке —
  полный срез: очередь/обслужено/ошибки/ретраи, prefill tok/s, decode tok/s,
  кэш, память (MemAvailable/Total, swap), GPU (temp, sclk, power, busy),
  Tctl CPU — всё, что укладывается.
- Клавиши: минимум — `q` (выход), `+/-` (интервал), пауза логов.

## Дизайн UI (эскиз-контракт; архитектура уточняет, но блоки обязательны)

- Сетка блоков: «движок» (модель, uptime, очередь, ошибки, τ), «железо»
  (sclk, busy, power, GPU temp, Tctl), «скорость», «память»
  (MemAvailable/Total + bar, swap, KV pages), «логи» (ring-buffer, нижняя
  зона на всю ширину).
- **Скорости (D8, честные метрики; движок не отдаёт live-скорость в
  процессе — счётчики токенов обновляются только в done)**:
  decode tok/s = `recent_tok_s` (последний завершённый запрос);
  prefill tok/s = среднее гистограммы; активность в работе — очередь,
  GPU busy и sparkline по дельтам счётчиков (пики на завершении).
  Подписи строк НЕ обещают «live».
- **Логи (D9)**: зона сидируется `podman logs --tail 50` при старте +
  live-поток `podman logs -f`; «(ждём логи…)» — только пока и сид пуст,
  и новых строк нет.
- Минимальный терминал 80×24 (SSH); при меньшем — деградация, не краш.
- Сервер упал: блок «движок» показывает «недоступен», блоки RAM/датчиков/логи
  продолжают жить (в отличие от стрим-режима, завязанного на /stats).
- Пороги цветом: MemAvailable < 10 GiB — красный; Tctl > 80° — красный;
  busy≈0 при queue>0 — подсветка подозрения на зависание.

## Ограничения

- Изменения движка hipfire не допускаются: все данные уже отдаются
  `/stats`, `/metrics` и host sysfs (FACTS.md).
- Python — только stdlib (curses, urllib, subprocess); bash — домашний стиль
  аннотаций; репо без IP/хостов/ключей (правило 7 AGENTS.md).
- `--interval N` сохраняется (default 2 с); интервал — период перерисовки TUI
  и период строчки стрим-режима.
