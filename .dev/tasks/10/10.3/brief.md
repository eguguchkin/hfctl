# Brief: watch/cache-tok-temp — «Cache tok» с тысячами + пороги температур

Сабстэдж продукта hfctl (дашборд `hfctl watch`). Инициатива пользователя
(2026-11-14), записана в бэклог hflab (`STATE.md`, пункт 8, коммит `3d807de`),
формулировки уточнены пользователем же (см. «Решения»).

## Решения (канон, от пользователя)

1. **Cache**: метрика движка — только кумулятивный счётчик ТОКЕНОВ
   (`hipfire_cached_prompt_tokens_total`; байтового размера кэша движок не
   отдаёт — проверено на живом `/metrics` che-evo 2026-11-14). Никаких
   выдуманных МБ: строка переименовывается в **`Cache tok`** и печатается
   **в тысячах**: `<1000` — целое как сейчас, `≥1000` — `99.1k`
   (одна десятичная, суффикс `k`; `≥1_000_000` — `1.2M`). Тот же формат —
   в plain-стриме (не-TTY), включая тестовые константы selfcheck.
2. **Температуры (CPU temp и GPU temp, оба)**: жёлтый **80…89 °C**,
   красный **≥90 °C**, иначе без подсветки. Сейчас: CPU краснеет при >80,
   GPU без подсветки → заменить на двухпороговую схему. «Оранжевый» =
   жёлтый (решение пользователя: настоящий custom-color не нужен).
   В TUI — атрибуты curses; в plain-стриме ANSI ТОЛЬКО если stdout — TTY
   (в pipe цветных кодов быть не должно).

## Goal

Дашборд честно показывает кэш (токены, компактно) и предупреждает цветом о
нагреве по явным порогам 80/90 — в обоих режимах (`watch` TUI и plain).

## DoD

1. TUI: строка `Cache tok` с новым форматом; `CPU temp`/`GPU temp` —
   жёлтый 80–89, красный ≥90 (ровно границы: 79.9 — нет, 80.0 — жёлтый,
   89.9 — жёлтый, 90.0 — красный; сравнение по факту round-то, как печатается).
2. Plain-стрим: тот же текст (`cache tok: 99.1k`) и те же пороги; ANSI при
   не-TTY не печатается (проверка: `hfctl watch | cat` без escape-кодов).
3. Пороги/формат — чистые функции, покрыты selfcheck (`--selfcheck` все
   проверки зелёные; новые проверки на формат k/M и на границы 80/90
   добавлены, число проверок в отчёте).
4. Ничего лишнего: блок «Память», sparkline'ы, лог-зона, `p`, usage — не
   затронуты; `tpl/bench/` не тронут (md5 `253c7ac5`); движок/стек не
   трогаем (правка чисто презентационная).
5. Внешняя приёмка (EXP, делает оркестратор на машине B по tmux/SSH):
   TUI виден с новой подсветкой и `Cache tok`; plain через pipe без ANSI;
   реальный результат — в hflab `.local-analysis/` (правило 7).
6. Доставка по D12: после пуша пользователем; обе машины уже на образе
   0.4.6, правка диспетчера — копия файлов, без переподъёма стека.

## Constraints and traps

- Правки только в `tpl/python/watch_tui.py` (+ доки/spec при необходимости);
  `lib/commands.sh`-слой `watch` не меняется (он только вызывает TUI/plain).
- `selfcheck`-константы (`PLAIN_FULL`/`PLAIN_MIN`, `metrics` фикстуры) —
  обновить согласованно, иначе selfcheck упадёт.
- curses `init_pair` уже есть (C_RED/C_YELLOW/C_GREEN) — новый pair НЕ нужен.
- Не менять семантику числа (только способ печати); счётчик кумулятивный —
  не превращать в дельту (пользователь просил переименование+формат).
- TUI-минимум 80×24: `Cache tok: 1.2M` короче прежнего — колонка не поедет.
