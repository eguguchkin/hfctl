### 2. Новая геометрия `draw()` (точные формулы)

Старые правила (фиксированная `bh = (avail-1)//2`, `gap = 1`,
`log_h = max(6|3, (H-1)//4)`) **заменяются** наполняющими:

```
# строка 0 — статус-бар (§5).
if H < 4 or W < 8:  return                          # только статус-бар (как есть)
if H < 10:                                                 # 1+3+3+3=10 — сетка не влезает
    log_h = 3;  log_top = H - 3                        # только статус-бар + «Логи» (рамка+заголовок),
    [box + заголовок «Логи», контента НЕТ (§2.1)]
    return
c_e = len(engine_rows)   # 1 («недоступен») или 6..8 (§4)
c_h = len(hw_rows) = 5
c_s = len(speed_rows) = 4
c_m = len(mem_rows) = 3
h1 = max(c_e, c_h) + 3          # ряд 1: заголовок(1) + контент(max пары) + 2 рамки
h2 = max(c_s, c_m) + 3          # ряд 2: то же
LOG_MIN = 3                     # «Логи»: рамка+заголовок+рамка, 0 контент-строк
rem = H - 1 - h1 - h2           # остаток вертикали для «Логи» (растёт при H>24)
if rem < LOG_MIN:               # клип — только когда суммарно не хватает строк
    deficit = LOG_MIN - rem
    c1, c2 = h1 - 3, h2 - 3     # контент-строк в рядах (c1 ≥ 1 всегда: c_e ≥ 1)
    d1 = min(c1, deficit * c1 // (c1 + c2))   # целочисленно, ряд 1 — первым
    d2 = min(c2, deficit - d1)
    h1 -= d1;  h2 -= d2         # блок не ниже 3 строк (заголовок без контента)
log_h = H - 1 - h1 - h2         # = rem (без клипа) или LOG_MIN (после клипа); ≥ 3 при H ≥ 10
col_w = max(10, W // 2);  x2 = W - col_w
block(0, 1,     col_w, h1, 'Движок',   engine_rows)
if W >= 2 * col_w:  block(x2, 1,      col_w, h1, 'Железо',   hw_rows)   # W<20 — правая колонка не рисуется (перекрытие исключено)
block(0, 1 + h1, col_w, h2, 'Скорость', speed_rows)
if W >= 2 * col_w:  block(x2, 1 + h1, col_w, h2, 'Память',   mem_rows)
log_top = 1 + h1 + h2
box(0, log_top, W, log_h);  put(log_top + 1, 2, 'Логи')
```

Свойства (контракт):
- **Между рядами нет ни одной пустой строки**: верхняя рамка ряда 2 стоит
  на строке `1 + h1` (непосредственно под нижней рамкой ряда 1 на `h1`).
  `gap` — константа 0, формулы с `gap`/`(avail-1)//2`/`(H-1)//4` удаляются.
- Блоки ряда одинаковой высоты = максимум пары; меньший блок добирает
  пустыми контент-строкАМИ (не пустыми строками МЕЖДУ рядами — это разные вещи).
- «Логи» = остаток вертикали: при росте H растёт (80×30 → 10 контент-строк),
  при нехватке — держит `LOG_MIN = 3`; клип — только контент-хвосты блоков
  (`block()` отбрасывает строки снизу, как сейчас), рамки никогда не рвутся.

Точные ожидаемые значения (UTF-8, `engine_ok=True`; c_e=6 — типовое
состояние errors=0/retries=0):

| Тёрминал | h1 / h2 / log_h | Видимые контент-строки |
|---|---|---|
| 80×24 (c_e=6) | 9 / 7 / 7 (контент 4) | ряд 1 y1..9, ряд 2 y10..16, логи y17..23 (контент y19..22); Движок 6 строк (Model/Uptime/Queue/τ avg/Served/Cache), Железо 5 + 1 пустая; Скорость 4, Память 3 + 1 пустая |
| 80×24 (c_e=8, errors>0 и retries≠0) | 11 / 7 / 5 (контент 2) | ВСЕ 8 строк Движка видимы (контракт review #4 расширяется: теперь видны и Served/Cache) |
| 80×24 (engine_ok=False, c_e=1) | 8 / 7 / 8 (контент 5) | «недоступен» 1 строка, Железо 5 + 2 пустые |
| 80×30 (c_e=6) | 9 / 7 / 13 (контент 10) | «Логи» растёт |
| 60×15 (W=60: col_w=30) | 6 / 5 / 3 (контент 0) | deficit=5 → d1=3, d2=2: Движок 3 (Model/Uptime/Queue), Железо 3 (GPU freq/GPU load/GPU power), Скорость 2 (decode/prefill), Память 2 (RAM/Swap); логи = рамка+«Логи»+рамка |
| 40×10 (W=40: col_w=20) | 3 / 3 / 3 | deficit=10 → d1=6, d2=4: оба ряда — заголовок только, логи — заголовок только (как было) |
| H=16 | 7 / 5 / 3 | deficit=4 → d1=2, d2=2: Движок 4 (…+τ avg), Железо 4 (…+GPU temp), Скорость 2, Память 2 |
| 4 ≤ H < 10 (например 80×8) | — | статус-бар + «Логи» (3 строки снизу), ряды не рисуются |

### 2.1 Лог-зона (контент и placeholder)

```
если log_view не пуст:  lines = log_view[-(log_h - 3):]  → put(log_top + 2 + i, 2, ln)
иначе (пусто) — ТОЛЬКО если log_h ≥ 4:  put(log_top + 2, 2, '(ждём логи…)')
```
- При `log_h = 3` (минимум) контент/placeholder НЕ рисуются — зона =
  рамка + «Логи» + рамка (устраняет перезапись нижней рамки placeholder'ом
  при минимальной высоте).
- Контент-строки никогда не заходят за нижнюю рамку: `log_top + 2 + (log_h - 4) = H - 2`.

### 3. `block()` — выравнивание и клип (DoD 6)

```
lw = max(len(label) + 1 for label, *_ in rows)  # «+1» = знак ':'; пустые rows → 0
строка = (label + ':').ljust(lw) + ' ' + value[:max(0, w - lw - 4)]
put(yy, x + 2, строка, attr)
```
- Все значения блока начинаются с колонки `x + 3 + lw` (одна колонка на
  блок; ярлык дополнен точками до max-длины ярлыка блока + `:` + 1 пробел).
- Клип значения: последняя колонка значения ≤ `x + w - 2` — рамка `x+w−1`
  никогда не перезаписывается, зазор ≥ 1 колонка.
- Отбрасывание строк — хвостом (`break` при `yy >= y + h - 1`), как сейчас;
  приоритет строк = порядок в списке `rows_*` (обязательные первыми —
  канон review #4 для «Движка» сохраняется дословно).
- Приоритет клипа в блоках (хвост списка = отбрасывается первым):
  Железо → CPU temp, затем GPU temp; Скорость → spark decode, spark prefill
  (sparkline — вторичный элемент); Память → KV pages, Swap.

### 4. Названия (DoD 4, 5) — фиксированная таблица

Названия блоков (во всех режимах, включая ASCII-глифы и selfcheck):
**«Движок», «Железо», «Скорость», «Память», «Логи»**.

Ярлыки метрик (ТUI-блоки; значения и порядок строк — не меняются;
plain-строка — не трогается):

| Блок | Было | Стало |
|---|---|---|
| Движок | модель / uptime / очередь / ошибки / τ avg / обслужено / ретраи / кэш | **Model / Uptime / Queue / Errors / τ avg / Served / Retries / Cache** |
| Железо | sclk / busy / power / GPU temp / Tctl | **GPU freq / GPU load / GPU power / GPU temp / CPU temp** |
| Скорость | decode / prefill / spark prefill / spark decode | без изменений (уже читаемы) |
| Память | mem / swap / KV pages | **RAM / Swap / KV pages** («KV pages» остаётся, `-` вне slot-режима — как есть) |

- Порядок строк всех блоков — как сейчас (в т.ч. канон review #4:
  Model, Uptime, Queue, [Errors >0], τ avg, [Served], [Retries ≠0], Cache).
- «τ avg» в ASCII-режиме — «tau avg» (через `Glyphs.tau`, как сейчас).
- Строка при engine_ok=False — «недоступен» (строчная, это состояние,
  не метрика — не капсируем).
- Форматы значений НЕ меняются: Tctl — 1 знак (`fmt_c`, 39.1C — остаётся
  дробным); GPU temp/power — целые (`fmti`, существующий дом-выбор,
  review round 1 некритичные #7); sclk — `fmti` MHz. См. Open questions #2.
- Пороги цветом привязаны к строкам, а не к старым ярлыкам:
  `CPU temp` > 80° — красный (attr строки), `GPU load` < 5% при queue>0 —
  жёлтый/bold, `RAM` < 10 GiB — красный. Код атрибутов не трогается.
- Ширины: sparkline `width = max(4, W // 2 - 18)` (было `W // 2 - 4`;
  review round 2 некритичные #1 — влезает в рамку, свежие точки не
  отбрасываются: `sparkline()` уже берёт `vals[-width:]`).
  Окно истории НЕ меняется: `maxlen = max(1, 60 // interval)` (≈60 с).
- Bar Памяти: `width = max(4, min(10, W // 2 - 30))` (было
  `min(24, max(6, W // 2 - 25))`). Проверено: на 80×24 типичное значение
  ` <bar10> 45.2/60.4 GiB` = 25 зн. ≤ бюджета 27 (w−lw−4), worst case
  `999.9/999.9` = 27 зн. = бюджет → зазор 1 колонка, рамка цела.

### 5. Статус-бар (DoD 7) — формулировка и геометрия

Тексты (фиксированы):
- bullet: `●` (зелёный при engine_ok, красный иначе) — колонка **0**;
  колонка **1** — пустая (разрыв 1 колонка); левый текст — колонка **2**.
- left = `'hfctl watch │ модель '` + модель (усечение ниже).
- mid = `'интервал N c'` (без изменений).
- right — самодостаточная подпись `p` (состояние + действие):
  - live: `'логи: live, пауза: p │ q — выход'` (32 зн.)
  - пауза: `'логи: пауза, live: p │ q — выход'` (32 зн.)

Формулы `status_bar_layout(W, interval, model, paused)` (возврат — 7-кортеж):

```
prefix = 'hfctl watch │ модель '            # 21 зн.
right_x = max(0, W - len(right) - 1)
mid_x   = max(0, min(W // 2 - len(mid) // 2, right_x - len(mid) - 1))
model_w = mid_x - len(prefix) - 3           # <0 → модель '' (left = prefix)
left    = prefix + model[:max(0, model_w)]
draw_mid   = mid_x   > 2 + len(left)        # иначе mid не рисуется (деградация ниже минимума)
draw_right = right_x > 2 + len(left)        # иначе right не рисуется
```

`draw()`: bullet x=0; left x=2 (было x=1); mid при `draw_mid`; right при
`draw_right`. На W ≥ 79 наложений нет никогда; на W < 80 (ниже минимума)
mid/right отбрасываются целиком (не наезжают, put() не клипает «наполовину»).

Проверено для W=80 (live и paused — идентичная геометрия):
right_x=47, mid_x=34, model_w=10, left=31 зн. (колонки 2..32),
mid 34..45, right 47..78, колонка 79 пуста; разрывы: bullet→left = 1,
left→mid = 1, mid→right = 1 (контракт fix round 2 «разрыв ≥1 перед
интервал» сохранён, ассерт стал строгим по обе стороны).
W=60: left=prefix (2..22), mid НЕ рисуется (mid_x=14 < 24), right 27..58 —
без наложений. W=40: только left (2..22).

### 6. Лог-зона: дубль seed/live (DoD 9) — механизм

Причина дубля: live-процесс `podman logs -t --tail 1 -f` ре-эммитит
последнюю строку сида как свою первую (штатная семантика `--tail 1`).

Механизм (в `LogStreamer`):
```
self._seed_tail = None
seed():  lines = ...; self.buf.extend(lines)
         self._seed_tail = lines[-1] if lines else None   # хвост сида
_spawn_once():  for line in proc.stdout:
         line = line.rstrip('\n')
         if self._seed_tail is not None and line == self._seed_tail:
             self._seed_tail = None      # первая строка live = повтор хвоста сида → отбрасываем
             continue
         self._seed_tail = None          # сравнение — ТОЛЬКО первую строку live-процесса
         self.buf.append(line)
```

Edge-кейсы (контракт):
- **Сид пуст** (нет podman/контейнера, rc≠0, таймаут): `_seed_tail = None`
  → дедупа нет, все live-строки добавляются (зона работает как сейчас).
- Live-процесс ре-спавнен (контейнер упал/пересоздан): `_seed_tail` уже
  `None` (потреблён первым спавном) → дедупа нет — корректно: новый
  контейнер = новый поток логов.
- Pathological: версия podman, которая НЕ ре-эммитит tail-1, при этом первая
  live-строка случайно равна хвосту сида → одна идентичная строка потеряна.
  Допустимо (один раз при старте); комментарий в коде 1 строкой.
- Пауза/буферизация — не меняются (deque, maxlen 500).

### 7. `selfcheck()` — новые/изменённые кейсы (итого 38/38)

Из существующих 30 кейсов меняется 1: `status bar 80 cols gap≥1` →
7-кортеж, ассерты: `draw_mid and draw_right and mid_x - 2 - len(left) >= 1
and mid_x + len(mid) < right_x and right_x + len(right) <= 80`.
Новые (8):
1. `status bar 60 cols` — W=60: `draw_mid is False`, `draw_right is True`,
   `right_x + len(right) <= 60`, наложения нет (`right_x > 2 + len(left)`).
2. `status bar 40 cols` — W=40: `draw_right is False`, `right_x + len(right) > 40 or not draw_right` (правый не наезжает на left).
3. `seed/live no dup` — fake-podman-шим (PATH): режим без `-f` печатает `A`;
   режим с `-f` печатает `A`, затем `B`. Один экземпляр: `seed()` +
   `_spawn_once()` → `list(buf) == ['A', 'B']` (дубля нет).
4. `seed empty: live no dedup` — шим: без `-f` rc=1 (без строк); с `-f`
   печатает `C` → `seed()` (buf пуст, `_seed_tail=None`) + `_spawn_once()`
   → `list(buf) == ['C']`.
5. `sparkline tail kept` — 30 значений, `width=22`: длина 22, последний
   глиф = глиф последнего значения (свежие не отброшены).
6. `hardware labels` — `[r[0] for r in w.rows_hardware(fix)] ==
   ['GPU freq', 'GPU load', 'GPU power', 'GPU temp', 'CPU temp']`.
7. `engine labels` — порядок+названия по fix-snap (errors=2, retries=1):
   `['Model','Uptime','Queue','Errors', w.glyphs.tau + ' avg', 'Served',
   'Retries','Cache']` (τ через `w.glyphs` — детерминировано при любом TERM).
8. `KV pages dash` — `rows_memory` с `kv_free/kv_total=None` → строка
   `('KV pages', '-')` присутствует (строка не прячется).

### 8. Usage rc=1 (DoD 10)

Где рождается: диспетчер `hfctl`, ветка `""` роутера (строка ~230) —
`usage` возвращает 0, скрипт завершается с 0. Правка ровно одна строка:
`usage` → `usage; exit 1` (usage остаётся на stdout; `usage()` не
terminating — как сейчас). Синхронизировать комментарии: в `usage()`
(«выход на совести вызывающего…») и в комментарии роутера (ветка `''`).
- Влияние на алиасы: **нет** — `up|down|mode|autostart|noautostart|_boot|
  _watchdog` имеют собственные ветки case; ветка `""` срабатывает только
  при нуле аргументов. Ветка `*` (неизвестная команда) уже `exit 1`.
- Internal checks AGENTS.md (`hfctl` без аргументов → usage, rc=1) —
  выполняется; доки уже говорят rc=1 (spec/hfctl.md:36 «внятный отказ …
  rc 1» описывает ошибки, bare-вызов под этот же контракт) — доки НЕ править.
- Проверено: `install.sh` и `lib/` bare-`hfctl` без аргументов не вызывают.

### 10. Edge-кейсы (ожидаемое поведение, сводка)

| Кейс | Поведение |
|---|---|
| Пустой контент (engine_ok=False) | Движок = 1 строка «недоступен»; h1 = max(1,5)+3 = 8 (железо определяет); остальные блоки живут; 80×24 → логи 8 строк (контент 5) |
| Недоступный сервер (mёртвый порт) | Как сейчас: блок «недоступен», sysfs/RAM/логи живут, цикл без краха |
| Пустой лог-вид | «(ждём логи…)» — только при log_h ≥ 4 и пустом буфере (D9) |
| ASCII-режим (TERM=dumb/posix, UTF-8 locale) | Рамки `+---|`, глифы `. -:*#%@`, `°C`→`C`, `τ`→`tau`, `●`→`o`; **названия блоков — те же кириллические** (в UTF-8 locale кодируются); статус-бар-тексты — те же |
| Не-UTF-8 locale (C) | ASCII-глифы; кириллические строки молча пропускаются `put()` (UnicodeEncodeError ловится — существующее поведение, не краш) |
| H < 4 или W < 8 | Только статус-бар (существующий guard) |
| 4 ≤ H < 10 | Статус-бар + «Логи» (3 строки снизу), ряды не рисуются |

## Risks and rollback

- **Переписана вся геометрия draw()** — главный риск регрессии (рамки/
  наложения). Митигация: точные ожидаемые значения §2 + grid-чек в 4
  размерах и обоих состояниях + pty-грид; доконтракт review #4
  (обязательные строки Движка на 80×24) проверяется grid-кем при c_e=8.
- **Статус-бар: усечение модели стало на 1 знак короче** (10 вместо 11
  при W=80 — bullet сдвинулся на колонку). Косметика, контракт fix round 2
  (gap ≥1) держится (selfcheck строгий).
- **Ниже минимума (W<80) mid/right отбрасываются целиком** — было «mid
  сдвигается влево, put() клипует»; теперь чище (без наложений — урок
  fix round 2), но на 60×15 «интервал» не виден (допустимо: ниже минимума).
- **Док-синхронизация** (spec/hfctl.md/README): если не сделать — reviewer
  закроет (расхождение док-контракта); spec/state.md — НЕ трогать
  (оркестратор, статусный коммит).
- **EXP-001 ложный FAIL**: скрипт грейпит старые lowercase-имена и «Tctl» —
  тестер ОБЯЗАН обновить критерии ДО перепуска (brief DoD 12, constraint).
- **Rollback**: behavior-only (ни state, ни конфиги, ни модели, ни plain);
  откат = revert коммита. Живые машины миграции не требуют.

## Open questions

Блокирующих НЕТ (все ветки зафиксированы в Design). Неблокирующие:

1. **Чтение DoD 1: «второй ряд начинается непосредственно с нижней рамки
   первого ряда».** Реализация в контракте: `gap = 0` (ряд 2 начинается на
   строке сразу ПОД нижней рамкой ряда 1; рамки не разделяются, но не
   совпадают). Альтернатива — «разделяемая рамка» (верхняя рамка ряда 2
   рисуется НА строке нижней рамки ряда 1, htop-стиль; экономит ещё 1
   строку, но требует спец-рисования углов). Рекомендация: gap = 0
   (проще, требование «без пустых строк» закрыто). Если после визуального
   просмотра пользователь захочет разделяемую рамку — design-уровневый
   fix round (формулы §2 сдвигаются на −1 строку).
2. **«Дробные температуры сохраняются» (DoD 5).** Контракт фиксирует: Tctl
   — 1 знак (как сейчас); GPU temp/power — целые (существующий дом-выбор,
   review некритичные #7 round 1: «осознанная асимметрия»; «значения НЕ
   менять — только ярлыки»). Если пользователь имел в виду «GPU temp тоже
   дробным» — одна строка (`fmti` → `fmt_c` в `rows_hardware`),
   design-уровневый fix round.
3. **Язык ярлыков метрик.** Контракт: английский (примеры пользователя —
   «CPU temp», «GPU freq»; продуктовый словарь уже полу-английский;
   названия блоков — русские по DoD 4). Если предпочтительнее русские
   ярлыки — единая точка правки (таблица §4), fix round.
