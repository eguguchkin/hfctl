# Brief: defects/polish — KillMode-коммент в юните + сравнение temp по печатаемому

Механический пакет из двух найденных мелочей. Инициатива: ревизия хвостов
2026-11-14 (hflab STATE.md пункты 9а и заметка ревьюера watch/cache-tok-temp).

## Факты

- `tpl/systemd/hipfire-compose.service.tpl:8`: `KillMode=process          #
  не убивать cgroup контейнеров при остановке юнита` — systemd inline-комменты
  после значения НЕ понимает; в journal на обеих машинах с 2026-11-12:
  `hipfire-compose.service:8: Failed to parse kill mode specification,
  ignoring: process          # …`. Директива фактически не применяется.
  Watchdog-шаблон (`hipfire-compose-watchdog.service.tpl:6-8`) делает это
  правильно — комментарий СТРОКОЙ ВЫШЕ.
- `tpl/python/watch_tui.py` `temp_color()`: сравнение сырого `deg` с
  порогами 80/90, а печатается округлённым (`fmt_c`): 79.95 покажется «80.0»
  без подсветки. Бриф watch/cache-tok-temp говорил «как печатается».

## Goal

Юнит парсится без предупреждений и реально несёт задуманную директиву;
цвет температуры соответствует напечатанному числу.

## DoD

1. Шаблон: комментарий над строкой `KillMode=process`; рендеренный файл
   проверяется `systemd-analyze verify` (или `systemctl --user cat`-эквивалент
   на смонтированном unit-файле в песочнице) БЕЗ «Failed to parse».
2. `temp_color` сравнивает число ровно так, как его печатает `fmt_c`
   (CPU — дробное с 1 знаком, GPU — целое через fmti; проверить обе строки);
   selfcheck: границы 79.95→печатается 80.0→жёлтый, 89.96→90.0→красный,
   прежние 48 проверок не сломаны.
3. Локально (без машин): `bash -n`, рендер шаблона (подстановка __STACK_DIR__)
   в /tmp + verify, selfcheck rc=0, git status = только два файла + артефакты.
4. Машинная часть (юнит-файлы на машинах обновятся только после пуша +
   доставки + пересоздания юнитов `hfctl off/on` или install) — ЗА
   оркестратором в отдельном окне даунтайма (правило пользователя
   2026-11-14: одна машина за раз, предупреждение заранее). В этом
   сабстэдже машины НЕ трогаем.
