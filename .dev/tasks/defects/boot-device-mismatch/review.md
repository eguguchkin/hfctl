### Особые опасения (проверены по коду, не по отчётам)

- **(а) recreate-цикл / чужие контейнеры — безопасно.** `hf_up_devsafe`
  делает ровно один retry (третьего up нет); `_boot` ограничен дедлайном
  420 с + потолком 48 итераций; вотчдог — одиночный вызов за тик. rm только
  по лейблу `io.podman.compose.project=hipfire`, что согласовано с
  фиксированным `STACK_DIR=$HOME/hipfire` и `CONTAINER=hipfire_hipfire_1`;
  чужие compose-проекты (другой лейбл) не затрагиваются; пустой `ps -aq` →
  no-op под `|| true`. Деградация при смене лейбла = прежнее поведение,
  задокументирована в контракте функции.
- **(б) тихий отказ вотчдога — реальные сбои не съедает.** Порядок гейтов:
  маркер `.hfctl-stopped` ПЕРВЫМ (явная остановка уважается даже без GPU),
  GPU-гейт вторым. При готовом GPU и мёртвом контейнере — строка в лог +
  `hf_up_devsafe` (selfcheck «д»): подлинные падения стека обрабатываются.
  Молчание только при отсутствующих GPU-нодах — выбор, разрешённый брифом
  («single-check с отказом-тишины»), зафиксирован в dev-report. См.
  non-critical №1 про видимость.
- **(в) GPU-ready wait не вешает юнит.** `gpu_ready_or_die`: дедлайн
  старт+60 с, шаг 2 с, по таймауту `die` с диагностикой (kfd есть/нет +
  `ls /dev/dri`) → rc 1 → юнит перезапускается сам (tpl проверен:
  `Restart=on-failure`, `RestartSec=30`), внешняя крышка
  `TimeoutStartSec=900`. Selfcheck «в»: rc 1, 0 вызовов up, FATAL+диагностика
  в stderr.
- **(г) штатный путь не замедлен.** `gpu_ready_or_die` при наличии нод
  выходит мгновенно (нулевая цена в нормальном буте); `hf_up_devsafe` на
  счастливом пути = прежний `hf_up_locked` + один `podman inspect`; при
  up→running ни rm, ни второго up (selfcheck «а»: 1 up/0 rm; «ж»: 0/0).
- **Регрессия on/off/use/install** — не затронута: дифф не содержит тел
  `cmd_up`/`hf_up_locked` (только коммент-контракт), `cmd_on/off/autostart`,
  `install.sh`, `tpl/`. `py_compile` OK; `./hfctl` → usage rc=1;
  `HFCTL_PORT=1 status --json` → rc=0 graceful.
- **Спека-честность**: секция boot-механизма SPEC.md переписана в той же
  дельте, протухшего текста («force-recreate со 2-й попытки») не осталось —
  оставшиеся упоминания force-recreate в SPEC — живой use-путь и явная
  пометка «механизм удалён».

   артефактах задач (`.dev/tasks/.../brief.md`, `dev-report.md`) —
   устоявшаяся практика коммит-хистори `.dev/` (STATE/PLAN полны имён) —
