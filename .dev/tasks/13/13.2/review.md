## По рискам из задания

- **(а) контент-паритет limits**: логика страхует ровно как контрактовано — `cmp -s` → запись только при расхождении (stack.sh:146-150); байт-паритет рендера прежним выводу подтверждён (tpl 2 строки + `\n`-хвост render_tpl == старые echo/tee), т.е. на машинах с файлом от host_prep записи не будет. Рукописный файл с теми же значениями, но иными байтами → один sudo-перезапись каноном: поведение сервера то же, exit 42 не встанет (лимит сессии уже применён/unlimited — чек stack.sh:151-155 стоит только сразу после записи). Риск задекларирован в контракте Risks, проверка — EXP-хвост. Не блокирует.
- **(б) exit 42 наверху**: preflight зовётся прямым вызовом в процессе диспетчера — cmd_install (commands.sh:58) и cmd_use (commands.sh:153), без сабшелла/подстановки → exit 42 = rc процесса, как и до дельты (точки exit 42 те же две). Наверху ничего не меняется.
- **(в) unshare/os-release**: адаптация только в tests/run_checks.sh:34-36,42-46 — re-exec под `unshare -rm` + bind /etc/os-release внутри собственного namespace; `grep -rn unshare lib/ hfctl tpl/` — пусто. Прод-код не затронут.
