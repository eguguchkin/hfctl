   репликацией): `check_mutation` делает `bash -n autostart.sh stack.sh
   stack_files.sh`, а bash -n парсит только первый аргумент (остальные
   становятся позиционными) — проверен фактически только autostart.sh.
   Следствие: мутант gpu-gate НЕ парсится (вырез info-строки пустит else-ветку
   → `syntax error near fi`), но батарея отчитала «сценарий упал — защита
   держит»: сценарий упал из-за краша source'а непарсящегося stack.sh, а не
   по ассерту; по собственному контракту батареи честный вердикт был бы
   «мутант не парсится». Защита по существу держит — доказано синтаксически
   валидным мутантом (строка → `:` no-op): P-C RED на ассерте «GPU-подготовка
   пропущена». Баг guard'а дофиксовый (HEAD:411 идентичен), 13.2 — первый
   маркер с непарсящимся мутантом; claim task.md «sed-удаление не ломает
   синтаксис» неверен для gpu-gate. Бэклог на след. раунд тестов (не продукт,
   13.2 DoD не нарушает): цикл `bash -n` по файлам в check_mutation + маркер
   gpu-gate на синтаксически самодостаточную строку.
